# سامانه حسابداری و انبار قطعات خودرو | حسابداری پورکیان

این پروژه بر اساس سند نیازمندی پیوست‌شده ساخته شده است: رابط کاربری فارسی و راست‌چین، ثبت سریع فروش، خرید دستی و PDF/OCR، دو انبار مستقل، دفتر اشخاص و تعمیرگاه، ردیابی محموله FIFO، گزارش سود، چک، قالب چاپ و API آماده اتصال کانال‌های فروش.

## نکته مهم درباره بستر فنی

سند، **Laravel 12 + PHP 8.3 + MySQL/MariaDB** را برای استقرار نهایی روی Laragon/VPS تعیین می‌کند. محیط اجرای این پیش‌نمایش PHP/Composer نداشت؛ بنابراین نسخه‌ای که اکنون اجرا می‌شود از **FastAPI + SQLite** استفاده می‌کند تا جریان‌های اصلی را واقعاً قابل استفاده و آزمایش کند. منطق و ساختار داده‌ها مطابق نیازمندی کسب‌وکار است، اما این پوشه هنوز پروژه Laravel نیست و نباید به‌عنوان استقرار تولیدی Laravel معرفی شود. برای بهره‌برداری نهایی طبق سند باید لایه API/ORM به Laravel 12 و MySQL منتقل و HTTPS، سیاست نگهداری پشتیبان و تست پذیرش محیط مشتری تکمیل شود.

## اجرای محلی

### Linux / macOS

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

برای OCR فاکتور اسکن‌شده، Tesseract و بسته زبان فارسی لازم است. در Debian/Ubuntu:

```bash
sudo apt-get install tesseract-ocr tesseract-ocr-fas
```

سپس از ریشه پروژه اجرا کنید:

```bash
bash run.sh
```

### Windows

1. Python 3.10 یا بالاتر را نصب کنید.
2. برای OCR اسکن، Tesseract را همراه زبان فارسی `fas` نصب و به `PATH` اضافه کنید.
3. فایل `run_windows.bat` را اجرا کنید؛ یا در PowerShell:

```powershell
python -m pip install -r requirements.txt
cd backend
python -m uvicorn main:app --host 0.0.0.0 --port 8000
```

در مرورگر میزبان `http://127.0.0.1:8000` را باز کنید. برای دسترسی LAN، میزبان را روی شبکه داخلی مجاز کنید و پورت 8000 را در Firewall محدود به شبکه فروشگاه نگه دارید.

## مدیریت کاربران

اطلاعات ورود توسط مدیر اصلی از بخش تنظیمات و کاربران ایجاد یا ویرایش می‌شود.


## مسیر آزمایش سریع

1. با حساب مدیر وارد شوید.
2. در **فروش سریع**، کالا را با بارکد یا نام جست‌وجو کنید؛ نوع مشتری قیمت پیش‌فرض خرده/عمده/همکار را تعیین می‌کند.
3. از **خرید و OCR** نمونه «PDF متنی» یا «اسکن ۳۰۰ DPI» را انتخاب کنید. نتایج را اصلاح/تأیید کنید؛ هیچ ردیف OCR بدون اقدام شما ثبت نمی‌شود.
4. از **انتقال بین انبارها** قطعه را به تعمیرگاه منتقل و در صورت نیاز سند مالی را هم ثبت کنید.
5. در **گزارش‌ها و سود** بازه شمسی را تعیین کنید؛ خروجی Excel برای فروش، موجودی و گردش اشخاص در دسترس است.
6. در **تنظیمات ← پشتیبان‌گیری** نسخه بسازید/دانلود کنید و آزمون بازکردن پایگاه داده را اجرا کنید.

## محدوده پیاده‌سازی‌شده

- کالا، بارکد یکتا، بارکد داخلی `AP-1405-####`، محصول والد/متغیر، قیمت‌های خرده/عمده/همکار، سابقه قیمت و حذف نرم.
- موجودی تفکیک‌شده فروشگاه/تعمیرگاه، سند تعدیل با علت، دفتر گردش کالا و محموله‌های خرید.
- خرید دستی و آپلود PDF متنی/اسکن، OCR فارسی با Tesseract (`fas+eng`، رندر ۳۰۰ DPI)، پیشنهاد تطبیق بارکد/نام مستعار/نام مشابه و صفحه بازبینی قبل از ثبت.
- فروش با چند روش دریافت، چک، مانده اعتباری، سقف اعتبار مشتری، هشدار موجودی منفی و فروش زیر حداقل.
- محاسبه بهای تمام‌شده فروش از محموله FIFO و ذخیره snapshot قیمت‌ها و هزینه در فاکتور نهایی.
- مرجوعی خرید/فروش، انتقال داخلی، حساب مستقل تعمیرگاه و گردش خدمات/تسویه.
- گزارش فروش و سود، ارزش موجودی، بدهی/بستانکاری، پیگیری چک، خروجی XLSX، چاپ A4/A5 و «چاپ/ذخیره PDF» مرورگر.
- کاربر و نقش، ثبت ردپا، توکن‌های API کانال، پیش‌نویس سفارش آنلاین، پشتیبان ZIP روزانه/دستی و آزمون یکپارچگی SQLite.

## نکات مالی و داده‌ای

- مبالغ در پایگاه داده با واحد **ریال** و عدد صحیح ذخیره می‌شوند؛ رابط کاربری امکان نمایش ریال یا تومان دارد (هر تومان = ۱۰ ریال).
- SQLite در `data/erp.sqlite` قرار می‌گیرد؛ پیوست‌های PDF در `data/uploads/` و پشتیبان ZIP در `backups/` هستند.
- اسناد نهایی فروش/خرید بازنویسی نمی‌شوند؛ تغییرات از طریق سند مرجوعی، تسویه یا تعدیل ثبت می‌گردند.
- اگر فروش در موجودی منفی مجاز باشد، برای بخش فاقد محموله، بهای جاری کالا به‌صورت **برآوردی** ذخیره و فاکتور علامت‌گذاری می‌شود؛ سود چنین ردیفی تا تهیه موجودی واقعی نیازمند بازبینی مدیریتی است.
- فاکتور رسمی، مالیات ارزش افزوده، اتصال زنده ووکامرس/ترب/باسلام، همگام‌سازی آفلاین و دفتر حسابداری دوطرفه کامل در محدوده نسخه اول نیستند.

## API

- مستندات محلی: `/api-docs`
- سلامت سرویس: `/health`
- نشست برنامه: `POST /api/auth/login`، سپس `Authorization: Bearer <session>`
- کانال‌ها: `GET /api/channel/v1/products`، `/inventory`، `/prices` و `POST /api/channel/v1/orders` با توکن API دارای مجوز محدود.
- سفارش آنلاین به شکل `DRAFT` ذخیره می‌شود و تا بازبینی انسانی موجودی را کم نمی‌کند.

```text
frontend/index.html   رابط تک‌صفحه‌ای فارسی و راست‌چین
samples/              دو PDF آزمایشی (متنی و اسکن‌شده ۳۰۰ DPI)
data/                 پایگاه داده و فایل‌های آپلودی
backups/              فایل‌های پشتیبان ZIP
```
